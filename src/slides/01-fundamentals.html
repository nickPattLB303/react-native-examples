Native Development: Pros and Cons

Advantages

  • Best performance
  • Full access to platform features
  • Platform-specific design patterns
  • First-class support for new OS features
  • No abstraction layer overhead

Challenges

  • Separate codebases for iOS and Android
  • Different programming languages
  • Duplicate development effort
  • Higher maintenance costs
  • Need for specialized developers
Key Insight: Native development offers the best performance and platform integration but at the cost of maintaining separate codebases and teams.

Platform-Specific Considerations

Android Developers

You'll recognize similarities between React Native's component-based architecture and Android's View system, though with significant differences in implementation. The declarative approach differs from imperative Android UI development.

iOS Developers

The declarative UI approach in React Native differs from UIKit's imperative style but shares conceptual similarities with SwiftUI. Component lifecycle is different from UIViewController lifecycle.

React Developers

You'll find the component model familiar, though React Native components map to native UI elements rather than DOM elements. Navigation patterns and styling are different from web development.

Angular Developers

React's unidirectional data flow differs from Angular's two-way binding, but the component-based architecture will feel familiar. React's JSX is different from Angular's template syntax.

Performance vs. Development Speed

Performance

  • Near-native performance for most use cases
  • Uses actual native UI components
  • JavaScript runs in separate thread
  • Performance bottlenecks at the bridge
  • Hermes engine improves JS performance

Development Speed

  • Single codebase for multiple platforms
  • Hot reloading for rapid iteration
  • Large ecosystem of libraries
  • Familiar web development paradigms
  • Expo tools for faster setup
Key Insight: React Native offers a compelling balance between performance and development speed for most applications. It's not as fast as fully native code, but the performance difference is negligible for many use cases, while development speed is significantly improved.

"Learn Once, Write Anywhere"

React Native Philosophy

Unlike "write once, run anywhere" approaches that often lead to lowest-common-denominator UIs, React Native embraces platform differences while sharing core logic.

What this means in practice:

  • Core business logic and components are shared
  • Platform-specific code when needed
  • Platform-specific file extensions (.ios.js, .android.js)
  • Platform module for conditional logic
TypeScript

import { Platform, StyleSheet } from 'react-native';

const styles = StyleSheet.create({
  container: {
    // Shared styles
    flex: 1,
    alignItems: 'center',
    
    // Platform-specific styles
    ...Platform.select({
      ios: {
        shadowColor: 'black',
        shadowOffset: { width: 0, height: 2 },
        shadowOpacity: 0.2,
      },
      android: {
        elevation: 4,
      },
    }),
  },
});

JavaScript and Native Threads

React Native's Threading Model

React Native runs on three separate threads:

Main Thread (UI Thread)

  • Native UI rendering
  • Native modules execution
  • User interactions

JavaScript Thread

  • React component logic
  • Business logic
  • Virtual DOM diffing

Shadow Thread

  • Layout calculations
  • Yoga layout engine
  • Flexbox implementation
Key Insight: This separation allows React Native to perform complex JavaScript operations without blocking the UI thread, but communication between threads can become a performance bottleneck.

Bridge Architecture

How the Bridge Works

  • Asynchronous communication between JS and native code
  • JSON messages passed between threads
  • Serialization and batching of messages
  • Bidirectional communication
JavaScript to Native Flow

1. React component calls native module method
2. JS Bridge serializes the call into JSON
3. Message is queued for native side
4. Native bridge deserializes the message
5. Native module executes the requested method
6. Results are serialized and sent back (if needed)
Performance Consideration: The bridge can become a bottleneck when passing large amounts of data (e.g., long lists, images, complex animations) due to serialization overhead.

The New Architecture

Fabric (UI Layer)

  • Reimplementation of rendering system
  • Synchronous rendering capabilities
  • Improved interoperability with native code
  • Better support for concurrent features

TurboModules

  • Lazy loading of native modules
  • Direct, synchronous communication
  • Type-safe interface
  • Improved startup performance

JavaScript Interface (JSI)

  • Direct references to native objects from JavaScript
  • No serialization/deserialization overhead
  • Enables synchronous communication
  • Foundation for both Fabric and TurboModules
Status: The new architecture is being gradually rolled out. It represents a significant improvement but requires migration effort for existing apps.

JavaScript Execution

JavaScript Engines

  • JavaScriptCore - Default engine
  • Hermes - Optimized for React Native
  • V8 - Used in development (Chrome)

Hermes Benefits

  • Faster startup time
  • Reduced memory usage
  • Smaller app size
  • Better performance on low-end devices

Compilation Approaches

  • Just-in-Time (JIT) - Compiles JavaScript at runtime (JavaScriptCore)
  • Ahead-of-Time (AOT) - Pre-compiles JavaScript (Hermes)
  • Bytecode - Hermes uses bytecode format for better performance
Recommendation: For production apps, Hermes is generally recommended for its performance benefits, especially on Android.
