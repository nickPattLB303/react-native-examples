Introduction

Welcome to Module 5 of our React Native Training Course! In this module, we'll explore TypeScript, a powerful superset of JavaScript that adds static typing to enhance your development experience.

TypeScript provides compile-time type checking, which helps catch errors early, improves code quality, and enhances developer productivity—especially in large-scale applications like healthcare and pharmacy systems.

Instructor notes: Begin by gauging participants' familiarity with TypeScript. Some may have experience with statically typed languages like Java or C#, which can be helpful reference points.

Learning Objectives

  • Understand the benefits of TypeScript in React Native development
  • Learn TypeScript's core type system and syntax
  • Apply TypeScript to React Native components and props
  • Use interfaces and types to model domain-specific data
  • Implement type-safe state management
  • Understand TypeScript configuration options
  • Apply best practices for TypeScript in React Native projects
Instructor notes: Emphasize that after this module, all subsequent code examples, exercises, and challenges will use TypeScript. This module builds the foundation for the rest of the course.

What is TypeScript?

Key Characteristics

  • Superset of JavaScript
  • Developed and maintained by Microsoft
  • Adds static typing to JavaScript
  • Compiles to plain JavaScript
  • Open source with active community
  • Supported by major frameworks (React, Angular, Vue)

TypeScript is a superset of JavaScript, meaning all JavaScript code is valid TypeScript code.

Instructor notes: Clarify that TypeScript doesn't run directly in browsers or on devices - it's compiled to JavaScript first. The TypeScript compiler (tsc) handles this conversion.

Why TypeScript?

Error Prevention

Catch type-related errors during development rather than at runtime

Better Tooling

Enhanced IDE support with autocompletion and inline documentation

Code Readability

Self-documenting code with explicit type annotations

Safer Refactoring

Compiler catches breaking changes when modifying code

Team Collaboration

Clear contracts between components and modules

Scalability

Better maintainability for large codebases

Instructor notes: Share a personal example of how TypeScript has helped prevent bugs in your own projects. Real-world examples make the benefits more tangible.

TypeScript in React Native

TypeScript is particularly valuable in React Native development:

  • Expo and React Native templates now include TypeScript by default
  • React Native's own codebase is written in TypeScript
  • Type definitions available for React Native APIs and components
  • Helps manage complex state and props in large applications
  • Improves reliability for mission-critical apps (like healthcare)

For pharmacy and healthcare applications, TypeScript's type safety is especially valuable when handling sensitive patient data, medication information, and complex business logic.

Instructor notes: Mention that many React Native libraries now provide TypeScript definitions, making the ecosystem more type-safe overall.

TypeScript Basics: Types

// Basic types
let medicationName: string = "Acetaminophen";
let dosageMg: number = 500;
let isGeneric: boolean = true;
let expirationDate: Date = new Date("2025-12-31");

// Arrays
let activeIngredients: string[] = ["acetaminophen", "caffeine"];
let dosageOptions: Array<number> = [250, 500, 1000];

// Tuple (fixed-length array with specific types)
let medicationInfo: [string, number, boolean] = ["Ibuprofen", 200, true];

// Enum
enum MedicationType {
  OTC = "Over the counter",
  PRESCRIPTION = "Prescription only",
  CONTROLLED = "Controlled substance"
}
let medicationType: MedicationType = MedicationType.OTC;
Instructor notes: Walk through each type example, explaining the syntax and use cases. Emphasize that TypeScript infers types when possible, so explicit annotations aren't always needed.

TypeScript Basics: Advanced Types

// Union types
let dosage: number | string = 500; // Can be number or string
dosage = "500mg twice daily";

// Type aliases
type MedicationID = string;
let medId: MedicationID = "MED-12345";

// Intersection types
type Contact = { phone: string; email: string };
type Address = { street: string; city: string; state: string; zip: string };
type Pharmacy = Contact & Address;

// Optional properties
type Prescription = {
  medication: string;
  dosage: string;
  refills: number;
  instructions?: string; // Optional property
};

// Literal types
type DosageUnit = "mg" | "mcg" | "mL" | "tablet";
let unit: DosageUnit = "mg"; // Can only be one of the specified values
Instructor notes: These advanced types provide more flexibility and precision. Highlight how union types and optional properties are particularly useful in React Native for handling different data states.

TypeScript Interfaces

// Basic interface
interface Medication {
  id: string;
  name: string;
  dosage: number;
  unit: string;
  isGeneric: boolean;
}

// Interface with optional and readonly properties
interface Patient {
  readonly id: string; // Cannot be changed after initialization
  name: string;
  dateOfBirth: Date;
  allergies?: string[]; // Optional property
}

// Interface extension
interface Prescription extends Medication {
  patientId: string;
  prescribedBy: string;
  date: Date;
  refills: number;
}

// Implementing interfaces in classes
class MedicationReminder implements Medication {
  id: string;
  name: string;
  dosage: number;
  unit: string;
  isGeneric: boolean;
  reminderTime: Date;
  
  constructor(med: Medication, time: Date) {
    this.id = med.id;
    this.name = med.name;
    this.dosage = med.dosage;
    this.unit = med.unit;
    this.isGeneric = med.isGeneric;
    this.reminderTime = time;
  }
}
Instructor notes: Explain the difference between interfaces and type aliases. Interfaces are often preferred for object shapes, especially when they might be extended. They're also more familiar to developers coming from OOP languages.

Type vs. Interface

Type Alias
// Definition
type Medication = {
  id: string;
  name: string;
  dosage: number;
};

// Union types
type MedicationStatus = 
  | "active" 
  | "discontinued" 
  | "recalled";

// Extending types
type PrescriptionMedication = Medication & {
  prescriptionId: string;
  refills: number;
};
Interface
// Definition
interface Medication {
  id: string;
  name: string;
  dosage: number;
}

// No direct union equivalent
// (would use type for this)

// Extending interfaces
interface PrescriptionMedication extends Medication {
  prescriptionId: string;
  refills: number;
}

When to use which?

Interfaces: For object shapes that might be extended or implemented by classes

Types: For unions, intersections, primitives, or when you need more complex type manipulations

Instructor notes: Both types and interfaces are useful, and the choice often comes down to team preference. In React Native projects, you'll typically see a mix of both.

Functions in TypeScript

// Function with parameter and return types
function calculateDosage(weightKg: number, dosagePerKg: number): number {
  return weightKg * dosagePerKg;
}

// Arrow function with type annotations
const calculateDailyDose = (dosagePerDose: number, frequency: number): number => {
  return dosagePerDose * frequency;
};

// Function with optional parameters
function createPrescription(
  medication: string, 
  dosage: number, 
  frequency: number, 
  duration?: number // Optional parameter
): string {
  let prescription = `${medication}, ${dosage}mg, ${frequency} times daily`;
  if (duration) {
    prescription += `, for ${duration} days`;
  }
  return prescription;
}

// Function with default parameters
function formatMedication(
  name: string, 
  dosage: number, 
  unit: string = "mg" // Default parameter
): string {
  return `${name} ${dosage}${unit}`;
}

// Function with rest parameters
function combineIngredients(mainIngredient: string, ...others: string[]): string {
  return `${mainIngredient} combined with ${others.join(", ")}`;
}
Instructor notes: Emphasize how TypeScript makes function signatures more explicit, which is especially helpful for API functions and callback props in React Native components.

TypeScript with React Hooks

import React, { useState, useEffect, useRef } from 'react';
import { View, Text, Button } from 'react-native';

// Type for our medication state
interface Medication {
  id: string;
  name: string;
  dosage: number;
  unit: string;
  takenAt: Date | null;
}

const MedicationTracker: React.FC = () => {
  // State with type annotation
  const [medications, setMedications] = useState([]);
  const [loading, setLoading] = useState(false);
  
  // Ref with type annotation
  const timerRef = useRef(null);
  
  // Effect to fetch medications
  useEffect(() => {
    const fetchMedications = async (): Promise => {
      setLoading(true);
      try {
        // In a real app, this would be an API call
        const data: Medication[] = [
          { id: '1', name: 'Aspirin', dosage: 500, unit: 'mg', takenAt: null },
          { id: '2', name: 'Ibuprofen', dosage: 200, unit: 'mg', takenAt: null }
        ];
        setMedications(data);
      } catch (error) {
        console.error('Error fetching medications:', error);
      } finally {
        setLoading(false);
      }
    };
    
    fetchMedications();
    
    // Cleanup function
    return () => {
      if (timerRef.current) {
        clearTimeout(timerRef.current);
      }
    };
  }, []);
  
  // Function to mark medication as taken
  const markAsTaken = (id: string): void => {
    setMedications(meds => 
      meds.map(med => 
        med.id === id 
          ? { ...med, takenAt: new Date() } 
          : med
      )
    );
  };
  
  return (
    <View>
      <Text>Medication Tracker</Text>
      {medications.map(med => (
        <View key={med.id}>
          <Text>{med.name} {med.dosage}{med.unit}</Text>
          <Text>
            {med.takenAt 
              ? `Taken at ${med.takenAt.toLocaleTimeString()}` 
              : 'Not taken yet'}
          </Text>
          <Button 
            title="Mark as Taken" 
            onPress={() => markAsTaken(med.id)} 
            disabled={med.takenAt !== null}
          />
        </View>
      ))}
    </View>
  );
};

TypeScript Configuration

tsconfig.json

{
  "compilerOptions": {
    "target": "esnext",
    "module": "commonjs",
    "lib": ["es2019"],
    "jsx": "react-native",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "moduleResolution": "node",
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noEmit": true
  },
  "exclude": [
    "node_modules",
    "babel.config.js",
    "metro.config.js"
  ]
}

Key Configuration Options

  • strict: Enables all strict type checking options
  • jsx: Controls how JSX is transformed
  • target: ECMAScript target version
  • lib: List of library files to include
  • moduleResolution: How modules are resolved
  • skipLibCheck: Skip type checking of declaration files

Expo and React Native CLI projects include a pre-configured tsconfig.json file. You can customize it based on your project's needs.

Instructor notes: Explain that the tsconfig.json file controls the TypeScript compiler. Most React Native projects won't need to modify this file significantly, but understanding the options can be helpful for advanced use cases.

TypeScript Best Practices

Use Strict Mode

Enable strict mode in tsconfig.json to catch more potential issues

Avoid any

The any type defeats TypeScript's purpose. Use unknown for truly unknown types

Prefer Interfaces for Objects

Use interfaces for object shapes, especially when they might be extended

Use Type Aliases for Unions

Type aliases are better for union types and complex type manipulations

Organize Types

Keep related types in dedicated files (e.g., types.ts) for better organization

Use Enums for Constants

Enums provide type safety for related constant values

Instructor notes: These best practices help teams get the most out of TypeScript. Emphasize that TypeScript should make development easier, not harder - if it feels like a burden, the team might need to adjust their approach.

Relating to Your Experience

TypeScript concepts can be related to your existing knowledge:

For Android Developers: TypeScript's static typing will feel familiar if you're used to Java or Kotlin. Interfaces in TypeScript serve a similar purpose to interfaces in Java. TypeScript's type system is more flexible than Java's, with features like union types and structural typing.

For iOS Developers: If you're familiar with Swift, TypeScript's optional types (using ?) are similar to Swift's optionals. TypeScript interfaces are comparable to Swift protocols. TypeScript's type inference is also similar to Swift's type inference system.

For React Developers: TypeScript adds static typing to the React patterns you already know. PropTypes are replaced by TypeScript interfaces or types. TypeScript can help prevent common React errors like missing required props or passing props of the wrong type.

For Angular Developers: If you've used Angular, you're likely already familiar with TypeScript as it's Angular's primary language. The concepts transfer directly to React Native, though the component patterns are different. Angular's strong typing approach works well in React Native too.
