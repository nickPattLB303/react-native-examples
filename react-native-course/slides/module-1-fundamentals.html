Introduction

Welcome to the first module of our React Native Training Course! In this module, we'll explore the fundamentals of React Native, including its history, how it works under the hood, and why it's a powerful choice for mobile development.

React Native enables you to build mobile applications using JavaScript and React, while still achieving native-like performance and user experience.

What is React Native?

Key Characteristics

  • Created by Facebook (now Meta)
  • Uses JavaScript and React
  • Renders to native UI components
  • Single codebase for multiple platforms
  • Open source with active community

React Native vs. Other Approaches

Native: Platform-specific code (Swift/Kotlin)

Hybrid: Web technologies in WebViews

Cross-Platform: Shared codebase compiled to native

React Native: JavaScript bridge to native components

Instructor notes: Emphasize that React Native is not a hybrid approach - it actually uses real native components, which is why performance is better than WebView-based solutions.

How React Native Works

React Native connects JavaScript and native platforms through a "bridge" architecture:

  1. JavaScript code runs in a JavaScript thread
  2. Communication happens via the "bridge"
  3. Native modules execute platform-specific code
  4. UI is rendered with actual native components

Note: The new architecture (Fabric & TurboModules) is improving this process with direct synchronous calls between JavaScript and native code.

Instructor Tip: Draw this architecture on a whiteboard to help visualize the concept. Show how JavaScript instructions flow through the bridge to native components.

Instructor notes: This is a simplified explanation. The key point is that React Native is not just rendering web views - it's actually controlling native UI components through a bridge mechanism.

Relating to Your Experience

React Native concepts can be related to your existing knowledge:

For Android Developers: Think of React Native components as analogous to Android Views and ViewGroups. The JavaScript thread is similar to your main UI thread, while the native modules are like Android's JNI for native code.

For iOS Developers: React Native components map to UIKit elements. The component hierarchy is similar to your view hierarchy in UIViewController. Native modules are comparable to Objective-C/Swift bridging.

For React Developers: React Native uses the same component model and lifecycle as React for web. The main difference is that instead of rendering to DOM elements, you're rendering to native mobile components.

For Angular Developers: React Native's component model is different from Angular's, but the concept of a JavaScript framework controlling UI elements is similar. Think of React components as analogous to Angular components, but with a different syntax and lifecycle.

Instructor notes: Highlight the relevant platform comparisons based on your audience. This helps participants connect new concepts to their existing knowledge.

Why React Native?

Advantages

  • Single codebase for multiple platforms
  • Faster development cycles
  • Hot reloading for quick iteration
  • Large community and ecosystem
  • Familiar technology (JavaScript/React)
  • Native performance for most use cases
  • Code sharing with web React applications

Limitations

  • Complex native functionality may require platform-specific code
  • Performance considerations for highly demanding apps
  • Bridge overhead (being addressed in new architecture)
  • Dependency on third-party native modules
  • Keeping up with platform updates

Your First React Native Component

/**
 * A simple medication information component
 * 
 * This component displays basic information about a medication
 * including its name, dosage, and instructions.
 * 
 * @param {object} props - Component properties
 * @param {string} props.name - Medication name
 * @param {string} props.dosage - Medication dosage
 * @param {string} props.instructions - Usage instructions
 * @returns {JSX.Element} - The rendered component
 */
import React from 'react';
import { View, Text, StyleSheet } from 'react-native';

const MedicationInfo = ({ name, dosage, instructions }) => {
  return (
    <View style={styles.container}>
      <Text style={styles.name}>{name}</Text>
      <Text style={styles.dosage}>Dosage: {dosage}</Text>
      <Text style={styles.instructions}>{instructions}</Text>
    </View>
  );
};

const styles = StyleSheet.create({
  container: {
    padding: 16,
    backgroundColor: '#f8f9fa',
    borderRadius: 8,
    marginVertical: 8,
    borderLeftWidth: 4,
    borderLeftColor: '#3498db',
  },
  name: {
    fontSize: 18,
    fontWeight: 'bold',
    marginBottom: 8,
    color: '#2c3e50',
  },
  dosage: {
    fontSize: 16,
    fontWeight: '500',
    marginBottom: 8,
    color: '#3498db',
  },
  instructions: {
    fontSize: 14,
    color: '#7f8c8d',
  },
});

export default MedicationInfo;
Instructor notes: Walk through this code example, highlighting the JSDoc comments, component structure, and styling approach. Point out how this follows React patterns that web developers will recognize.
