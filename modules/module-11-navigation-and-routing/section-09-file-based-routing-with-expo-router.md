## Section 9: File-Based Routing with Expo Router\n\nThis section delves into the practical application of file-based routing using Expo Router. We\'ll explore how to structure your `app` directory to create different navigation patterns like stacks and tabs, handle dynamic routes for displaying specific data (e.g., medication details in SpeedyMeds), and utilize layout routes for shared UI and navigator configuration.\n\n> 🛣️ **(All Learners):** Ensure you have Expo Router set up in your project as outlined in the previous section. The examples here will build upon that initial configuration.\n\n### Core Content\n\n#### Conceptual Content: The `app` Directory in Depth\n\nAs introduced before, the `app` directory is the cornerstone of Expo Router. Every `.tsx`, `.ts`, `.jsx`, or `.js` file within this directory becomes a route. Expo Router maps the file paths to URL paths.\n\n- **Index Routes:** `index.tsx` files serve as the default route for a directory (e.g., `app/index.tsx` is `/`, `app/settings/index.tsx` is `/settings`).\n- **Named Routes:** `app/about.tsx` maps to `/about`.\n- **Nested Routes:** `app/dashboard/stats.tsx` maps to `/dashboard/stats`.\n\n#### Procedural Content: Creating Navigators with Layout Routes (`_layout.tsx`)\n\nLayout routes (`_layout.tsx`) are special files that define the navigation structure for a segment of your app. They export a React component that typically returns a navigator component from Expo Router (`Stack`, `Tabs`, `Drawer`).\n\n**1. Implementing a Stack Navigator:**\n\nA common use case is a root stack navigator for the entire app.\n\n `tsx\n   // app/_layout.tsx (Root Layout)\n   import { Stack } from \'expo-router/stack\';\n\n   export default function RootLayoutNav() {\n     return (\n       <Stack>\n         <Stack.Screen name=\"index\" options={{ title: \'SpeedyMeds Home\' }} />\n         <Stack.Screen name=\"profile\" options={{ title: \'User Profile\' }} />\n         <Stack.Screen name=\"medications/[id]\" options={{ title: \'Medication Details\' }} />\n         {/* Fallback screen for unmatched routes - optional */}\n         <Stack.Screen name=\"+not-found\" /> \n       </Stack>\n     );\n   }\n   `\n - In this `_layout.tsx`, `<Stack>` acts as the navigator for all files at the root of the `app` directory (like `index.tsx`, `profile.tsx`) and for matching dynamic routes like `medications/[id].tsx`.\n - `Stack.Screen` components within the layout configure how each route within this stack is presented (e.g., header title).\n - `+not-found.tsx` is a special convention. If you create an `app/+not-found.tsx` file, Expo Router will render it when no other route matches. The `Stack.Screen name=\"+not-found\"` makes it part of this stack, so it gets the stack\'s header.\n\n**2. Implementing a Tab Navigator:**\n\n You can create a tab-based layout using a route group and a `_layout.tsx` file within that group.\n\n **File Structure:**\n `\n   app/\n     (tabs)/              # Route group for tabs, doesn\'t affect URL\n       _layout.tsx        # Defines the Tab navigator\n       home.tsx           # Screen for the first tab (becomes /home)\n       prescriptions.tsx  # Screen for the second tab (becomes /prescriptions)\n       settings.tsx       # Screen for the third tab (becomes /settings)\n     index.tsx            # Could redirect to /home or be a splash screen\n     _layout.tsx          # Root Stack Layout (could present the (tabs) group)\n   `\n\n **Root Layout (`app/_layout.tsx`):** This might just present the `(tabs)` group.\n `tsx\n   // app/_layout.tsx\n   import { Stack } from \'expo-router/stack\';\n\n   export default function RootLayout() {\n     return (\n       <Stack>\n         <Stack.Screen name=\"(tabs)\" options={{ headerShown: false }} />\n         {/* Potentially other screens outside the tab layout, like a modal */}\n         <Stack.Screen name=\"modal\" options={{ presentation: \'modal\' }} />\n       </Stack>\n     );\n   }\n   `\n\n **Tabs Layout (`app/(tabs)/_layout.tsx`):**\n `tsx\n   // app/(tabs)/_layout.tsx\n   import { Tabs } from \'expo-router/tabs\';\n   import FontAwesome from \'@expo/vector-icons/FontAwesome\'; // Example icons\n\n   export default function TabLayout() {\n     return (\n       <Tabs screenOptions={{ tabBarActiveTintColor: \'blue\' }}>\n         <Tabs.Screen\n           name=\"home\"\n           options={{\n             title: \'Speedy Home\',\n             tabBarIcon: ({ color }) => <FontAwesome size={28} name=\"home\" color={color} />,\n           }}\n         />\n         <Tabs.Screen\n           name=\"prescriptions\"\n           options={{\n             title: \'My Meds\',\n             tabBarIcon: ({ color }) => <FontAwesome size={28} name=\"list-alt\" color={color} />,\n           }}\n         />\n         <Tabs.Screen\n           name=\"settings\"\n           options={{\n             title: \'Settings\',\n             tabBarIcon: ({ color }) => <FontAwesome size={28} name=\"cog\" color={color} />,\n           }}\n         />\n       </Tabs>\n     );\n   }\n   `\n - The `(tabs)` directory is a route group, so it doesn\'t add `/(tabs)/` to the URL. `app/(tabs)/home.tsx` is accessible at `/home`.\n - `app/(tabs)/_layout.tsx` uses `<Tabs>` to define the tab bar.\n - Each `<Tabs.Screen name=\"...\" />` corresponds to a file in the `(tabs)` directory (e.g., `name=\"home\"` links to `home.tsx`).\n - `options` on `Tabs.Screen` configure the tab\'s title and icon.\n\n**3. Nesting Navigators:**\n\n You can nest navigators. For example, one of your tabs might itself be a stack navigator.\n\n **File Structure for a Tab with a Stack:**\n `\n   app/\n     (tabs)/ \n       _layout.tsx              # Defines Tabs navigator\n       home.tsx                 # Simple screen for home tab\n       (medications)/           # Group for medications stack, part of the tabs\n         _layout.tsx          # Defines Stack for medications\n         index.tsx            # List of medications (route: /medications)\n         [id].tsx             # Detail for a medication (route: /medications/:id)\n       settings.tsx\n   `\n\n **Medications Stack Layout (`app/(tabs)/(medications)/_layout.tsx`):**\n `tsx\n   // app/(tabs)/(medications)/_layout.tsx\n   import { Stack } from \'expo-router/stack\';\n\n   export default function MedicationsStackLayout() {\n     return (\n       <Stack>\n         <Stack.Screen name=\"index\" options={{ title: \'Current Medications\' }} />\n         <Stack.Screen name=\"[id]\" options={{ title: \'Medication Details\' }} />\n       </Stack>\n     );\n   }\n   `\n In your `app/(tabs)/_layout.tsx` (the Tabs layout), you would then refer to this stack:\n `tsx\n   // app/(tabs)/_layout.tsx snippet\n   <Tabs.Screen \n     name=\"(medications)\" // This refers to the (medications) directory \n     options={{\n       title: \'Medications\',\n       headerShown: false, // The stack inside (medications) will provide its own header\n       tabBarIcon: ({ color }) => <FontAwesome size={28} name=\"medkit\" color={color} />,\n     }}\n   />\n   `\n\n#### Procedural Content: Handling Dynamic Routes and Parameters\n\nDynamic routes allow you to create screens for an arbitrary number of items, like medication details.\n\n**1. Creating a Dynamic Route File:**\n\n Create a file like `app/medications/[id].tsx`. The `[id]` part makes the `id` segment dynamic.\n\n**2. Accessing Dynamic Parameters:**\n\n Expo Router provides the `useLocalSearchParams` hook to access parameters from the current route, or `useGlobalSearchParams` for params anywhere in the path.\n\n `` tsx\n   // app/medications/[id].tsx\n   import React from \'react\';\n   import { View, Text, StyleSheet } from \'react-native\';\n   import { useLocalSearchParams, Stack } from \'expo-router\';\n\n   export default function MedicationDetailScreen() {\n     const { id } = useLocalSearchParams<{ id: string }>(); // Type the expected params\n\n     return (\n       <View style={styles.container}>\n         {/* Configure header title dynamically using Stack.Screen if not done in layout */}\n         <Stack.Screen options={{ title: `Medication: ${id}` }} />\n         <Text style={styles.title}>Details for Medication ID:</Text>\n         <Text style={styles.idText}>{id}</Text>\n         {/* Fetch and display medication data based on this ID */}\n       </View>\n     );\n   }\n   const styles = StyleSheet.create({\n     container: { flex: 1, alignItems: \'center\', justifyContent: \'center\', padding: 16 },\n     title: { fontSize: 20, marginBottom: 8 },\n     idText: { fontSize: 18, fontWeight: \'bold\' },\n   });\n    ``\n - `useLocalSearchParams<{ id: string }>()` retrieves the `id` parameter from the URL (e.g., if the path is `/medications/aspirin123`, `id` will be `\"aspirin123\"`). Typing it with `<{ id: string }>` provides type safety.\n - `<Stack.Screen options={{ title: \`Medication: ${id}\` }} />`can be used directly within the screen component to set screen options if not handled by a parent`\_layout.tsx`file. This demonstrates one way to set dynamic options directly.\n\n**3. Navigating to Dynamic Routes:**\n\n   Use the`<Link>`component or`router.push` with the actual path:\n\n   ```tsx\n   // In another screen, e.g., a list of medications\n   import { Link } from \'expo-router\';\n\n   // ...\n   <Link href=\"/medications/amoxicillin500\">View Amoxicillin Details</Link>\n   <Link href={{ pathname: \'/medications/[id]\', params: { id: \'ibuprofen200\' } }}>View Ibuprofen</Link>\n   ```\n   The second `<Link>`example shows how to pass parameters programmatically for typed routes if you have a more complex setup or are using a generated route type.\n\n> [!TIP]\n> For strongly-typed routes, Expo Router can generate types for your routes, allowing you to navigate with full type safety for paths and parameters. This often involves a build step or a CLI command.\n\n> 📚 **Official Documentation:**\n>\n> - [Expo Router: Routing (File Conventions)](https://docs.expo.dev/router/routing/)\n> - [Expo Router: Layouts](https://docs.expo.dev/router/layouts/)\n> - [Expo Router: Stack Navigator](https://docs.expo.dev/router/navigators/stack/)\n> - [Expo Router: Tabs Navigator](https://docs.expo.dev/router/navigators/tabs/)\n> - [Expo Router: Dynamic Routes](https://docs.expo.dev/router/routing/#dynamic-routes)\n> - [Expo Router:`useLocalSearchParams`](https://docs.expo.dev/router/reference/search-parameters/#uselocalsearchparams)\n> - [Expo Router: Type Safe Routes](https://docs.expo.dev/router/reference/typed-routes/)\n\n> 🌐 **(Web Developers using File-System Routers like Next.js):**\n>\n> **Key Takeaway:** The concepts of `\_layout.tsx`for shared UI,`(group)`for organizing routes without affecting URL paths, and dynamic segments`[param].tsx`are directly analogous.
