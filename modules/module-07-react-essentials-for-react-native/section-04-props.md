## Section 4: Props (Passing Data Down)\n\nComponents are rarely static; they often need to display different data or behave differently based on the context in which they are used. This is where **props** (short for \"properties\") come in. Props allow you to pass data from a parent component to a child component, making components dynamic and reusable.\n\n### What are Props?\n\nProps are arguments passed into React components. They are passed to components via HTML-like attributes in JSX and are received by the component as a single object argument. Think of them as function arguments for your components.\n\n**Key Characteristics of Props:**\n\n- **Data Flow:** Props are the primary way data flows downwards in a React application – from parent to child.\n- **Read-Only:** A component must **never** modify its own props. Props are immutable from the perspective of the component receiving them. If a component needs to change some data, that data should typically be managed as state (covered in the next section) in the component that owns the data (usually a parent component).\n- **Customizable:** They make components configurable and reusable in different contexts by allowing the parent to specify details.\n\n### Passing Props to a Component\n\nYou pass props to a component using attributes in JSX, similar to how you set attributes on HTML elements.\n\n`` tsx\nimport React from \'react\';\nimport { View, Text, StyleSheet } from \'react-native\';\n\n// Define the interface for the props\ninterface MedicationDisplayProps {\n  name: string;\n  dosage: string;\n  form: \'Tablet\' | \'Capsule\' | \'Syrup\'; // Using a union type for specific allowed values\n  timesPerDay?: number; // Optional prop\n}\n\nconst MedicationDisplay: React.FC<MedicationDisplayProps> = (props) => {\n  return (\n    <View style={styles.container}>\n      <Text style={styles.name}>Medication: {props.name}</Text>\n      <Text>Dosage: {props.dosage}</Text>\n      <Text>Form: {props.form}</Text>\n      {props.timesPerDay && <Text>Frequency: {props.timesPerDay} times a day</Text>}\n    </View>\n  );\n};\n\n// Parent component using MedicationDisplay\nconst PatientMedicationList = () => {\n  return (\n    <View>\n      <MedicationDisplay \n        name=\"Amoxicillin\" \n        dosage=\"250mg\" \n        form=\"Capsule\" \n        timesPerDay={3} \n      />\n      <MedicationDisplay \n        name=\"Ibuprofen\" \n        dosage=\"200mg\" \n        form=\"Tablet\" \n      />\n      {/* You can also pass other JavaScript expressions */}\n      <MedicationDisplay \n        name={(\"Paracetamol\").toUpperCase()} \n        dosage={`${500}mg`} \n        form=\"Syrup\"\n        timesPerDay={2 + 2}\n      />\n    </View>\n  );\n};\n\nconst styles = StyleSheet.create({\n  container: {\n    padding: 10,\n    borderBottomWidth: 1,\n    borderBottomColor: \'#eee\',\n    marginBottom: 10,\n  },\n  name: {\n    fontWeight: \'bold\',\n    fontSize: 16,\n  },\n});\n\nexport default PatientMedicationList;\n ``\n\n**Explanation of Passing Props:**\n\n- **String Literals:** `name=\"Amoxicillin\"` and `form=\"Capsule\"` pass string literals. These are enclosed in double quotes.\n- **JavaScript Expressions:** For any non-string value or for dynamic string values, you use curly braces `{}`.\n - `timesPerDay={3}`: Passes a number.\n - `name={(\"Paracetamol\").toUpperCase()}`: Passes the result of a JavaScript expression.\n - `dosage={\`${500}mg\`}`: Passes a template literal (which is a JavaScript expression).\n    -   `timesPerDay={2 + 2}`: Passes the result of an arithmetic operation.\n-   **Optional Props:** `timesPerDay?`in the`MedicationDisplayProps`interface is an optional prop. If`timesPerDay`is not provided (like for Ibuprofen),`props.timesPerDay`will be`undefined`. The component conditionally renders the frequency text: `{props.timesPerDay && <Text>Frequency: {props.timesPerDay} times a day</Text>}`.\n\n### Accessing Props Within a Component\n\nInside a functional component, props are received as the first argument, which is an object.\n\n1.  **Using the `props` Object Directly:**\n\n    ```tsx\n    const MedicationDisplay: React.FC<MedicationDisplayProps> = (props) => {\n      return (\n        <View>\n          <Text>Medication: {props.name}</Text>\n          <Text>Dosage: {props.dosage}</Text>\n        </View>\n      );\n    };\n    ```\n\n2.  **Destructuring Props:** It\'s very common to destructure the props object in the function parameters for more concise code.\n\n    ```tsx\n    const MedicationDisplay: React.FC<MedicationDisplayProps> = ({ name, dosage, form, timesPerDay }) => {\n      return (\n        <View style={styles.container}>\n          <Text style={styles.name}>Medication: {name}</Text>\n          <Text>Dosage: {dosage}</Text>\n          <Text>Form: {form}</Text>\n          {timesPerDay && <Text>Frequency: {timesPerDay} times a day</Text>}\n        </View>\n      );\n    };\n    ```\n    This makes the code cleaner as you don\'t need to repeatedly type `props.`.\n\n### Typing Props with TypeScript\n\nUsing TypeScript to define the shape of your props object is a best practice that significantly improves code quality and developer experience. It provides auto-completion and compile-time checks, catching errors early.\n\nWe did this in the example above with the `MedicationDisplayProps` interface:\n\n```typescript\ninterface MedicationDisplayProps {\n  name: string;\n  dosage: string;\n  form: \'Tablet\' | \'Capsule\' | \'Syrup\'; \n  timesPerDay?: number; \n}\n```\n\n-   `name: string;`: The `name`prop must be a string.\n-  `form: \'Tablet\' | \'Capsule\' | \'Syrup\';`: The `form`prop must be one of these specific string values (a union type).\n-  `timesPerDay?: number;`: The `timesPerDay`prop is optional (indicated by`?`) and, if provided, must be a number.\n\nIf you try to pass a prop with an incorrect type or omit a required prop, TypeScript will show an error.\n\n### The `children`Prop\n\nEvery component has a special prop called`children` . This prop contains whatever is passed between the opening and closing tags of a component when it\'s used.\n\n```tsx\nimport React, { ReactNode } from \'react\'; // Import ReactNode for typing children\nimport { View, Text, StyleSheet } from \'react-native\';\n\ninterface CardProps {\n  title: string;\n  children: ReactNode; // children can be any valid React node(s)\n}\n\nconst Card: React.FC<CardProps> = ({ title, children }) => {\n  return (\n    <View style={styles.cardContainer}>\n      <Text style={styles.cardTitle}>{title}</Text>\n      <View style={styles.cardContent}>\n        {children}\n      </View>\n    </View>\n  );\n};\n\n// Using the Card component\nconst PrescriptionDetails = () => {\n  return (\n    <Card title=\"Prescription RX123\">\n      <Text>Patient: John Doe</Text>\n      <Text>Medication: Lisinopril 10mg</Text>\n      <Text>Instructions: Take one tablet daily in the morning.</Text>\n      <MedicationDisplay name=\"Lisinopril\" dosage=\"10mg\" form=\"Tablet\" timesPerDay={1}/>\n    </Card>\n  );\n};\n\nconst styles = StyleSheet.create({\n  // ... (previous styles) ...\n  cardContainer: {\n    backgroundColor: \'#f9f9f9\',\n    borderRadius: 8,\n    padding: 15,\n    marginVertical: 10,\n    elevation: 3, // For Android shadow\n    shadowColor: \'#000\', // For iOS shadow\n    shadowOffset: { width: 0, height: 2 },\n    shadowOpacity: 0.1,\n    shadowRadius: 2,\n  },\n  cardTitle: {\n    fontSize: 18,\n    fontWeight: \'bold\',\n    marginBottom: 10,\n  },\n  cardContent: {\n    fontSize: 14,\n  }\n});\n\nexport default PrescriptionDetails;\n```\n\nIn this example:\n\n-   The  `Card`component is designed to be a generic container.\n-  `children: ReactNode;`in`CardProps`types the`children`prop.`ReactNode`is a type that can represent anything React can render (elements, strings, numbers, fragments, etc.).\n-   When`Card`is used in`PrescriptionDetails`, the `<Text>`elements and the`<MedicationDisplay>`component between`<Card>`and`</Card>`are passed as`props.children`to the`Card`component.\n\n> 🍏 **(iOS Developers):**\n>\n> **Comparison:** Passing data via props is somewhat analogous to initializing a`UIViewController`or`UIView`with data, or setting its properties after creation. The`children`prop concept is similar to how`UIView`contains subviews. The key difference is React\'s unidirectional data flow and declarative updates based on prop changes.\n>\n> **Key Takeaway:** Props are the configuration for your components. Think of them as the \"inputs\" that customize a component\'s appearance and behavior.\n\n> 🤖 **(Android Developers):**\n>\n> **Comparison:** Props are like attributes you set on your Views in XML layouts (e.g.,`android:text=\"Hello\"`) or parameters you pass to a custom View\'s constructor or setter methods. The `children`prop is akin to how`ViewGroup`s can contain child Views.\n>\n> **Key Takeaway:** Props allow you to create reusable UI building blocks whose content and behavior can be defined by their parent, similar to configuring standard Android UI widgets.\n\nProps are a fundamental concept for building dynamic and reusable UIs in React. By understanding how to pass and use them effectively with TypeScript, you can create well-structured and maintainable React Native applications.\n\n### Exercise 7.2: Passing and Using Props\n\n**Objective:** Enhance the `MedicationCard`component from the previous exercise to accept and display more detailed information via props.\n\n**Instructions:**\n\n1.
